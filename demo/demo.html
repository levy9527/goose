Goose · Migration Demo

Goose 不但能自动化 SQL，
还能自动化复杂的 Go 代码

一个 Postgres → SQLite 的真实迁移场景：初始化数据、跨库搬数据、联网拉数、改表结构，全部装进同一套「有序、可回滚」的迁移管线。

SQL 迁移 Go 迁移 跨库数据搬迁 运行时 HTTP 拉取 schema 变更

01要解决的问题

数据库迁移往往不只有 SQL：还要把源库数据搬到目标库、联网拉数据、再调整表结构。这些步骤互相依赖，顺序错了就会炸。

传统「只自动化脚本」的工具管不了 Go 代码，于是人肉/脚本只能：先建表 → 先改表 → 最后才单独跑 Go 拉数程序 → 程序写入的还是旧列名 title → 插入报错：no such column: title。

02数据流总览

两个数据库各有一套 goose 迁移，Goose 按时间戳顺序统一执行 SQL 与 Go 迁移。PG 源库已用静态种子数据初始化。

04核心：Go 迁移跨库搬数据 + 联网拉数

两段「纯 SQL 脚本表达不了」的能力——同时开两个数据库连接搬数据，以及运行时调用 HTTP 接口。

// A) 跨库搬数据：连 Postgres 读，写进 SQLite（同一迁移事务里）
func upCopyAppUserFromPg(ctx context.Context, tx *sql.Tx) error {
    pg, err := sql.Open("pgx", pgDSN())   // 打开 Postgres 源库
    defer pg.Close()
    rows, err := pg.QueryContext(ctx,
        `SELECT id, name, username, email, website FROM app_user ORDER BY id`)
    for rows.Next() {
        tx.ExecContext(ctx,                        // 写入 SQLite 目标表
            `INSERT INTO app_user (id, name, username, email, website)
             VALUES (?,?,?,?,?)`, ...)
    }
    // 返回 nil → goose 提交；返回 err → goose 自动回滚
}

// B) 联网拉数：GET /users/1/posts → 解码 JSON → 填充 post 表
func upFetchPosts(ctx context.Context, tx *sql.Tx) error {
    posts, err := api.FetchPosts(ctx)    // 运行时 HTTP 请求
    return api.InsertPosts(ctx, tx, posts) // 写入旧列 title
}

05好路径 vs 坏路径

✅ 好路径 · Goose 自动化

./demo/run_demo.sh
STEP 1  PG:  建表(SQL) + 静态种子数据(SQL)
STEP 2  SQLite: 建表 → Go跨库搬PG→SQLite → 建post
        → Go拉/posts(运行时HTTP) → 重命名 title→heading
✓ 全部成功，顺序由 goose 保证

❌ 坏路径 · 非自动化

./demo/run_bad.sh
schema 先建好并 rename → heading
Go 拉数程序最后才跑（仍写旧列 title）
!! INSERT FAILED:
   table post has no column named title

同一份「复杂 Go 代码」（HTTP 拉取 + 解码 + 插入）在两条路径里复用——区别只在顺序。Goose 用迁移框架锁死顺序，别的方式靠人肉排脚本，就排错了。

07怎么运行

前提：本机 127.0.0.1:5432 有可用 Postgres（postgres/postgres），且能访问外网 jsonplaceholder（post 拉数需联网）。

# 好路径（一键演示 goose 自动化）
./demo/run_demo.sh

# 坏路径（复现非自动化故障）
./demo/run_bad.sh

# 单步 / 自定义（goose 当库用，两个独立入口）
go run ./demo/runner/pg up          # 准备 PG 源库
go run ./demo/runner/sqlite up       # 跑 SQLite 目标库迁移
go run ./demo/runner/{pg|sqlite} {status|show|reset}

连接串可用环境变量覆盖：PG_DSN、PG_SUPER_DSN。每次 up 会重建数据库，可反复演示。

08几个关键实现点

问题做法
goose CLI 不能执行 .go 迁移CLI 只认编译进二进制的 Go 迁移，-dir 里未注册的 .go 会报错 → 用 runnerlib（goose 当库）import 迁移包触发 init() 注册，再调 goose.UpContext
PG/SQLite 分两个入口goose 的 Go 迁移注册在进程全局 map；若目录里没有 .go 文件，goose 会回退灌入全部已注册 Go 迁移。所以 PG（纯 SQL）与 SQLite（含 Go）必须各自独立进程，PG 入口不 import SQLite 迁移包
SQLite 驱动modernc.org/sqlite（纯 Go、无 cgo），无需额外编译
PG 驱动jackc/pgx/v5/stdlib，注册 pgx 驱动
可重复演示每次 up DROP+CREATE PG 库 / 删除 SQLite 文件
代码复用HTTP 拉取 + 插入逻辑集中在 demo/api，迁移与坏路径复用同一份
